# Mobile transaction-history import

The **Transactions** drawer page imports transaction-only JSON and Excel exports from My Lovely Craft mobile 1.9.0 or later. This page must be included in your web deployment before the live site can accept these files. SQLite remains a mobile backup format.

Choose **Upload transaction archive**, inspect counts, then **Append imported history**. New IDs append; identical IDs/content are skipped; changed existing records retain the local version. Historical quotation JPEGs travel with the archive and are verified against SHA-256 references. Catalog/workbook data is independent and is never replaced by transaction uploads.

History persists in a separate IndexedDB database in the current browser. It is not a server upload or synchronization with Google Sheets. Download JSON/Excel copies before clearing browser data or moving to another device. Downloads preserve the portable mobile archive and can be appended into the phone again. The readable Excel tables are for inspection; the hidden TransactionArchive sheet is authoritative for restoration.

Filters include customer/reference/product search, daily or From/To dates, sale/movement date basis, and cash direction. Date boundaries include the full day in Singapore time. Quotations always use creation dates and are excluded from actual sales/cash totals.

Open a receipt's **Financial view / Manage** action to view original items and saved costs. **Credit = money in; Debit = money out.** Edit its one cash movement's direction, amount, date and notes, then save. Original receipts, payment details and inventory remain unchanged. The default credit amount is the payment applied to the sale after change/overpayment. This is not an installment payment account.

Reports separate original sales and estimated sale profit from cash in/out. New mobile receipts capture cost evidence at sale; older/incomplete cost evidence shows total cost/profit as unavailable. Known item costs remain available as a subtotal. Print/save a financial PDF for one receipt or the filtered receipts. Cash movement edits do not rewrite historical balances recorded at sale.

Browser writes compare IndexedDB revisions atomically. If another tab saves first, reload history rather than overwrite that tab's records. Parsing, validation or storage errors retain the previous durable history. JSON payloads have a 32 MB limit; transaction Excel files have a 48 MB compressed limit and bounded archive contents. Narrow date ranges to split large archives.

The v1 portable contract is shared with the mobile project: format `my-lovely-craft-transactions`, version, exportedAt, customerReceipts, quotations, transactionEntries, and a SHA-256-keyed images map. Fixtures were generated by the real mobile pricing/receipt services and Android image/SQLite serializer; they contain invented sample records.
